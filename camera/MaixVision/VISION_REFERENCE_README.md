# 全流程视觉：参考项目思路的 MaixCAM 独立版本

## 使用哪个文件

- 新版：`vision_reference.py`。在 MaixVision 打开、运行，确认后安装为应用。只上传这个脚本即可，不依赖同目录的旧版文件。
- 原版：`vision.py`，此次未修改。
- 原版额外快照：`vision_original_20261025.py`，与本次开始时的原版逐字节一致。
- 新版独立参数：设备 `~/vision_reference_config.json`；示例为 `vision_reference_config.example.json`。
- 原版 `~/lab_thresholds.json` 保留，新版不读取、不覆盖。

一次只运行一个视觉应用，避免争用相机和串口。需要恢复时启动原版应用即可。此次没有安装到相机、没有烧录硬件。

## 参考了什么，以及怎样控制运算量

参考仓库 `yuanxiexie531-glitch/gcs-gold-medal` 的 `cv2_python/zongchengxu20250724chusai.py`：限定观察区域、HSV分割、形状筛选、多帧确认、主控发起任务后才识别。

此版本为重新实现，不是把原程序改名：

- 相机仍使用512×320，保持现有运动协议的坐标尺寸；每个观察区域缩到最多384像素宽再分析，并映射回原图坐标。
- 每次只运行请求的任务与相关颜色，不同时运行全套算法。
- 物块：HSV掩膜、3×3开闭运算、有限轮廓；每色最多6候选，每候选最多3次椭圆拟合，每次至多约160个采样点。完整轮廓规则时直接返回，不做旧版的多窗口圆弧遍历、距离变换和亚像素边缘搜索。
- 圆环：灰度阈值、有限轮廓椭圆、同心分组；最多64个轮廓，不做全图霍夫参数遍历。允许斜拍椭圆。
- 无神经网络、无线网络或后台识别线程。空闲只显示画面并允许采色，不输出识别结果。
- 检测间隔至少100ms，理论输出上限10Hz；这是软件限频，不是保证MaixCAM实测10帧。屏幕显示每次分析耗时，包含二维码解码，不含取帧、显示与串口的全部延迟。

未在真实MaixCAM上测量帧率、总延迟或抓取成功率。旧版和新版的中心拟合方法不同，切换后必须重新检查视觉目标像素与近车窗口，不能假定旧标定直接等效。

## 全流程如何接运动

串口不变：`/dev/ttyS2`、115200。只接受STM32的现有`CAM`请求，输出`VISION`结果，不主动控制底盘或机械臂。

| 主控请求 | 新版处理 | 结果 |
|---|---|---|
| `CAM,id,QR` | 设备自带二维码解码；四组任务码校验，3次一致 | `VISION,id,QR,156+123+516+231` |
| `CAM,id,TABLE,156,x,y` | 三个指定颜色各唯一，几何有效；取三个底座中心的平均值，中心5次稳定 | `VISION,id,TABLE,156,cx,cy` |
| `CAM,id,NEAR,1` | 只在固定近车区域找红色；进入固定夹取窗口且位置3次稳定 | `VISION,id,NEAR,1,2` |
| `CAM,id,RING,2` | 三组黑色同心环从左到右排序，全部位置3次稳定 | `VISION,id,RING,2,cx,cy` |
| `CAM,id,OCCUPIED,156,x,y` | 三色物块排成一行，三个位置3次稳定；输出中间底座中心，并保存左中右锚点 | `VISION,id,OCCUPIED,156,cx,cy` |
| `CAM,id,PICK,6` | 根据此前保存的工位锚点，判断浅蓝在左中右哪一个固定位置，3次一致 | `VISION,id,PICK,6,3` |
| `CAM,id,MAT,5,x,y` | 指定颜色唯一，底座中心3次稳定 | `VISION,id,MAT,5,cx,cy` |
| `CAM,id,IDLE` | 停止任务识别及回传，保留后续PICK所需的工位锚点 | 无串口输出 |

表中的`x,y`是主控提供的校准目标；视觉报告真实检测坐标，不把结果强行改成目标，也不在相机侧移动底盘。最终是否对准由现有ESP32代码决定。

- 原料区：到位→TABLE校准→车载转盘定位→RAW_READY机械臂预备→NEAR等目标→RAW_TAKE夹取。NEAR不需要三个物块同时可见，不根据颜色顺序推算物块“应该到了”。
- TABLE的平均中心假设三物块在圆台等角度分布，适用于当前三个物块摆放。它不是直接识别白色大圆台，也不是完整透视标定。
- 加工区：RING定位空工位；放完后用OCCUPIED中间物块校准；PICK以颜色选择固定左中右机械臂参数。拿走一件后不会把剩余两件重新编号。
- 新的TABLE/RING/OCCUPIED/QR请求清理旧工位锚点；同一请求重发不会清掉已收集的稳定样本；新编号重置稳定样本。
- 漏检、多候选、几何不合理、位置晃动均返回`VISION,id,NONE`，不重复发上一次成功值。现有ESP32负责等待超时、停止动作，并把所处环节发给App。相机屏幕显示正在识别、未找到/歧义、稳定收集中等状态；未新增通信错误码。
- App关闭视觉的“到位直接动作”模式不会请求这些识别任务，继续由固定参数执行。

## 首次上机调节

1. 先在MaixVision试运行新版，保持全流程未启动。
2. 在相机实体触摸屏长按1.5秒，进入HSV采样。用底部PREV/NEXT选颜色，点物块内部干净区域，再按SAVE保存。EXIT退出。红/黑/浅蓝优先；黄色、绿色、蓝色按实际任务需要采样。不要点高光、阴影、白底或屏幕顶部文字。
3. 新版有可直接试识别的默认HSV，不要求原版LAB标定。默认阈值不是现场实测；颜色不准必须采样或编辑独立JSON。
4. 蓝/浅蓝采样范围有重叠时，重叠像素会被排除，避免同一物块被识别成两个颜色；如果采完仍漏检，请在JSON中收窄两者的H/S/V范围，尤其不能仅凭“看起来浅一些”假定阈值一定能分开。
5. 相机位置必须让要校准的三个物块、三个圆环完整入镜。你之前图片中的下方红色物块有截断，程序会拒绝这种候选，不会据此输出不完整物块的假中心；需要先调整视野。
6. 机械臂停在现有原料近车抓取参数2对应的位置，人工将目标放到实际能夹到的位置，观察新版十字中心。将该中心写入JSON的`near_point`；默认`[256,260]`只是初值，不是实测抓取点。
7. 检查TABLE、RING、OCCUPIED的中心与App的视觉目标X/Y。若中心定义导致系统偏差，优先重新标定目标；`material_offset`只用于小范围统一补偿，不能代替相机或机械臂标定。
8. 最后以低速验证单件，再执行全流程。新版保持3次/5次稳定确认；物块持续高速运动时可能一直不够稳定，程序不会超时后猜测并触发夹取。

触摸仅在空闲时可用；运行中的主控请求会退出采样界面，防止标定界面阻塞协议。SAVE失败会显示提示；未保存的采样重启会丢失。没有触摸屏时直接在设备用户目录编辑JSON。

## 参数示例

`rois`均为原始512×320坐标，格式`[左,上,右,下]`。近车窗口必须完整位于NEAR区域内。

```json
{
  "rois": {"NEAR": [128,176,384,308]},
  "near_point": [256,260],
  "near_window": [18,12],
  "material_offset": [0.0,0.0]
}
```

此片段只说明字段含义；实际保存请使用完整示例文件，保留其余ROI和HSV字段。

`near_window`分别是X/Y半宽：默认允许中心距离抓取点±18/±12像素，同时要求连续3次中心变化不超过2像素。不要单纯放大窗口来掩盖抓取位置错误。
