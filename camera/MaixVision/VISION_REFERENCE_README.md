# 工创智能搬运视觉（STM32 v2）

唯一实现与上传入口是 `main.py`，MaixVision 安装时只包含此文件。`vision_reference.py` 仅为旧入口转发，不再复制算法。其他历史脚本不参与当前应用，不能同时运行。

## 比赛约定

依据《附件2-1 2027年第十届中国大学生工创大赛智能+》初赛规则第4—8页：

- 颜色编号：1红、2黄、3蓝、4绿、5黑、6浅蓝。
- 任务码为四组三位数，例如 `156+123+516+231`。第一、三组为两批相同三色物料的搬运顺序；第二组为第一批加工和暂存位置，第四组为第二批加工位置。第二批暂存按同色已有物料码垛，由 STM32 的 STACK 动作完成。
- 原料盘三件物料相隔120°、转向随机，6—10秒一圈，停留时间现场决定。TABLE 求中心与椭圆轨迹；NEAR 等目标色在轨迹近车端稳定后才回复，不预测固定转速或转向。
- 图3中的工位编号从左到右为3、2、1。视觉 PICK 返回的是图像左、中、右位置1、2、3，STM32 转为机械臂下标0、1、2；这个返回值不是比赛圆环编号。实车相机方向须核对一致。
- 当前实现适配上述初赛，决赛新增形状和任务格式待现场规则确定。

## 当前识别流程

1. QR：收到扫码请求才开启 USB 摄像头0，640×480原图解码，连续3次一致才回复。屏幕显示USB画面、二维码框和内容；退出扫码释放设备，打开或读取失败每秒重试当前请求。空闲预览仍使用物料摄像头。
2. TABLE：浮点 LAB 分割，指定三种颜色求转盘椭圆；连续5帧中心与几何稳定才回复，同时保存 NEAR 的轨迹。
3. NEAR：沿保存的轨迹找目标颜色，在近车端窗口连续5帧稳定才回复位置2。取走其他物料后继续使用该轨迹，不要求三件始终齐全。
4. RING：检测三个同心圆环组，返回请求的图像位置中心；默认 STM32 请求中间位置2。
5. OCCUPIED：使用同一套 LAB 阈值检测任务三色，按图像横坐标保存左、中、右锚点，回复中间物料中心。
6. PICK：使用同一套 LAB 阈值检测目标色并匹配保存的工位锚点，回复位置1—3。取走物料不改变剩余工位编号；歧义返回 NONE。

黑色分割先去除细线，并保留轮廓层级、排除空心环，避免外侧黑色圆环遮住实心物料轮廓。

STM32 的 FLOW_ALIGN 执行：底座180° → 粗调搜索 → 一次精调 → TABLE/OCCUPIED在最终位置重新识别，仅刷新缓存、不再移动。RING没有后续缓存，无需刷新。随后才允许取放；每次 PICK 前底座回180°。FLOW_UNALIGN 撤销的是底盘累计指令位移。

只在粗调收到明确 NONE 且已过1500ms观察窗口后移动搜索；无串口回复时 STM32 持续等待。相机不控制电机，不承担停车超时或动作统计。

## 串口

512×320图像坐标、115200波特率，保留现有 CAM/VISION 协议：

| 请求 | 回复 |
|---|---|
| `CAM,id,QR` | `VISION,id,QR,156+123+516+231` |
| `CAM,id,TABLE,156,256.0,160.0` | `VISION,id,TABLE,156,cx,cy` |
| `CAM,id,NEAR,1` | `VISION,id,NEAR,1,2` |
| `CAM,id,RING,2` | `VISION,id,RING,2,cx,cy` |
| `CAM,id,OCCUPIED,156,256.0,160.0` | `VISION,id,OCCUPIED,156,cx,cy` |
| `CAM,id,PICK,6` | `VISION,id,PICK,6,位置1至3` |
| `CAM,id,IDLE` | 不回复 |
| `ACK,id` | 停止该编号任务的识别和回复，等待下一条请求 |

未识别、歧义、尚未稳定都回复 `VISION,id,NONE`。分析间隔至少100ms，实际速度取决于设备。新任务使用新编号并重置稳定窗口；STM32按编号、模式和目标接收，旧编号结果丢弃。已移除未使用的MAT模式。

STM32接受结果后发送 `ACK,id\n`，相机收到当前任务的确认后停止识别和串口回复，显示 `ACK RECEIVED / WAIT NEXT COMMAND`，关闭USB扫码摄像头和补光，保留TABLE轨迹与OCCUPIED工位缓存。普通任务的NONE不确认；粗调只有过1500ms窗口后接受NONE时才确认。确认前相机继续识别、回复；确认丢失时STM32对重复结果再次确认。已确认任务的相同请求不会重新启动，下一次任务须换新编号。

STM32等待视觉结果期间每1000ms补发相同请求，编号不变，相机不会重置稳定窗口，粗调1500ms观察起点也不变。用于相机晚启动、重启或漏帧后的恢复；无回复仍等待，不触发搜索移动。屏幕LAST:NONE表示尚未收到有效请求，LAST:QR#编号才表示已进入扫码任务。

### 扫码不切换时看哪里

当前构建标识为 `20261029-preview-fix`。有效请求到达后，屏幕绿色显示 `COMMAND RECEIVED OK` 和完整指令；未收到有效指令时显示 `WAITING FOR VALID COMMAND`。确认画面先于USB打开显示，之后保留在预览画面中。屏幕右上角UP秒数持续增加才表示主循环仍在运行；异常退出会显示VISION ERROR，详细堆栈见MaixVision控制台。底部U2表示实际使用/dev/ttyS2，RX为累计接收字节，OK为有效请求数，BAD为被拒绝的非空/超长帧数，LAST为最近一次有效请求。没有有效请求时额外显示RX RAW原始字节，不能把收到噪声等同于收到扫码命令。

若App已经显示“读取任务二维码 / QR”，UP持续增加而RX始终为1、LAST:NONE，说明请求没有进入当前程序的接收流。检查STM32的PA0 TX到相机B1 RX方向；相机B0 TX到STM32 PA1 RX是返回方向，单独接通它不会让相机收到请求。两端都使用115200 8N1。RX增加且BAD增加时看RAW与控制台被拒绝帧；LAST:QR#编号后才排查USB打开/读帧或二维码内容。不要把未收到请求的问题归因于LAB标定。

默认 MaixCAM2 `/dev/ttyS2`：B0 TX、B1 RX。STM32 UART4：PA0 TX接相机RX，PA1 RX接相机TX，并共地。其他板型/接线按 `CAMERA_UART_DEVICE` 与 `CAMERA_UART_PINS` 配置，程序不扫描端口。扫码相机编号由 `QR_CAMERA_DEVICE` 配置。

## 标定与配置

- TABLE/NEAR/OCCUPIED/PICK：统一使用 `~/lab_thresholds.json` 的六色LAB阈值。空闲长按屏幕1.5秒进入标定，双击后对准中心确认采样，L/A/B按钮调阈值，NEXT保存当前颜色，所有物料模式立即共用；重启后自动读取。缺少目标颜色标定时返回NONE，TABLE/OCCUPIED/PICK显示NEED LAB。已有LAB标定文件可继续使用，无需转换HSV。
- `~/vision_reference_config.json` 只保留ROI与material_offset；RING只使用ROI，不依赖颜色标定。示例见 `vision_reference_config.example.json`。QR也不需要颜色标定。
- 旧JSON可继续读取，HSV阈值与多余的TABLE/NEAR固定ROI、near_point、near_window、calibrated被忽略，不要求删除旧文件。已移除HSV分割，不再维护第二套颜色参数。
- 标定中收到新任务立即结束标定，未提交的当前颜色恢复为磁盘值；已NEXT提交的颜色保留。
- 空闲圆台预览默认识别123（红、黄、蓝），可修改main.py顶部的IDLE_PREVIEW_TARGET；正式任务始终按STM32请求的颜色组合识别。预览不发串口结果、不建立正式抓取缓存。屏幕底部RX/LAST帮助判断是否收到主控请求。
- 外接补光使用MaixCAM2 PW5/B3的GPIO高电平开、低电平关，任务和标定时开启。按规则只能垂直向下补光，需由实际安装保证。

安装后在设备设置中选择此应用开机自启。更新本版时需同时更新STM32固件，以配合最终位置缓存刷新与底座观察姿态。

## 验证

运行 `python yundong_part/tests/reference_vision_test.py` 检查当前main.py；运行 `python yundong_partv2/tests/run_tests.py` 检查STM32流程。测试包含最终校准位置的轨迹/工位刷新、取走物料后的编号保持、串口、USB恢复及标定中断。

模拟测试不能替代实机标定。仍需现场验证相机朝向、物料色差、光照、像素距离比例、机械臂姿态及抓取成功率；视觉回复成功不等于实物已经抓稳或码垛成功。规则要求的车载任务码显示和正确次数统计由整机另外实现。

本版显示保留512×320完整摄像头图像，底部追加100像素独立串口状态区；识别坐标不变。预览绘制直接保留到显示帧。LAB文件顶层和颜色参数必须是字典，格式错误时回退预设值并保持未标定状态。
