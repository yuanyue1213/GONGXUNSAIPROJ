# 原料区：圆台中心校准与近车位等待取料

全流程可开启“使用默认任务码”，使用156+123+516+231并跳过扫码，仍需视觉完成
原料到位等待和各工位颜色/位置识别。开关关闭时恢复扫码；该功能需更新App与ESP32，
视觉脚本和STM32沿用已支持BODY_NEAR_V3的版本。默认码模式路线标识为BODY_NEAR_DEFAULT_V1，
移动路线、抓放参数与BODY_NEAR_V3相同。


机械臂运动现采用[姿态点联动和平滑插值](../../yundong_part/shared/ARM_REFERENCE_MOTION.md)。
RAW_READY仍在外部抓取点暂停，RAW_TAKE从合爪继续；夹爪按配置速度实际插值，
10°/s移动30°需3秒。原料视觉几何与颜色等待规则不变。


当前协议版本是 `BODY_NEAR_V3`。原料区仅使用画面下方的一个固定抓取位，
按任务码等待目标颜色转来；其他工位仍使用固定左/中/右位置参数。
旧BODY_V1、BODY_LMR_V2不能启动新版ESP32的全流程。

## 斜拍与颜色干扰修正（2026-10-24）

圆台检测不再要求画面中的三边近似相等。保留实际三物块在同一圆形轨迹上、等角120°
分布的前提，用三点二阶矩估计斜拍后的椭圆。中心仍是三点均值，轨迹矩阵为
`M = 2/3 * sum((p-center)(p-center)^T)`；近车位置取椭圆画面Y最大的点：
`center + (Mxy/sqrt(Myy), sqrt(Myy))`。椭圆有倾角时，近车点X也会偏移，
不再使用“中心X不变、中心Y加平均半径”的正圆近似。

- 每色保留多个合格轮廓，联合比较三色的几何、面积与圆度，不直接拿最大黑色块。
  截断在图像边缘的轮廓、超大区域、过小目标先排除；每色超过6个候选时拒绝猜测。
- 三物块轮廓面积比默认不超过3倍，椭圆短长轴比至少0.4，点间距至少15像素。
  三点重合、近共线或几何范围异常仍拒绝，不能仅靠放宽三角形门槛接受任意点。
- 多组同样合理的候选无法分辨时，显示ambiguous_colors并返回NONE。
- 中心仍要求5帧在中位中心1像素内；同时检查5帧近车点波动不超过2像素，
  用这5帧的轨迹矩阵锁定椭圆，而不是用最后一帧噪声决定抓取点。
- 锁定后TABLE在轨迹区域内追踪；NEAR只保留椭圆轨迹环带内的候选，并参考该颜色
  校准时的轮廓面积，排除圆台外的大色块。轨迹内仍有多个同色候选则继续等，不选最近的冒充。
- 拿走物块后保留已标定椭圆。空闲预览若连续15帧失去原几何，可重新获取，但仍须重新
  通过完整5帧稳定检测，不能沿用旧坐标作为新识别结果。

这是针对常见斜拍的仿射椭圆模型，并非完整相机透视标定。仍要求三个物块原始位置等角、
同轨迹且可见，严重透视、不同高度、遮挡或照明变化需现场验证。LAB颜色轮廓质心仍是
当前观测点，不等同于独立拟合的物块底座圆心，抓取姿态需按实际相机安装位置标定。

复现用的100×80像素椭圆中，旧近车点误差约10.14像素（窗口8像素），修正后约0.33像素，
目标在真实下方位置稳定5帧可以通过。较大黑色干扰物场景也能选择回正确黑块。
合成图像、串口主循环、缺色与歧义等21项测试通过，尚未完成相机实机验证。

## 单独运行时的圆台预览

旧版出现WAIT CAM REQUEST表示未收到STM32的CAM请求，此时还没有运行圆台识别。
全流程只有到原料区、机械臂参考姿态完成后才请求TABLE，打开MaixVision本身不会触发任务。

新版vision.py在空闲和CAM/IDLE时自动预览156（红、黑、浅蓝）圆台，显示三色中心、
整体中心及稳定时的下方近车参考圈。预览只画到屏幕，不发送串口结果，不触发机械动作。
预览使用独立的检测器；收到正式请求时重新积累5帧，不能把预览坐标作为任务结果。
正式任务检测颜色仍取自CAM请求，预览156不会改变任务码。

| 画面状态 | 含义与处理 |
|---|---|
| PREVIEW TABLE 156 / WAIT CAM | 空闲本地预览，等待控制板正式请求 |
| NEED LAB: red/black/light_blue | 所列颜色未标定；空闲时长按1.5秒进入LAB标定并保存 |
| MISSING: black等 | 已有标定，但本帧未找到所列颜色，检查阈值、遮挡与光照 |
| invalid_triangle | 点间距过小、近共线、椭圆过扁或几何范围异常 |
| ambiguous_colors | 存在多组合理候选或候选过多，暂不选择 |
| unstable_geometry | 中心或近车点的轨迹几何尚未稳定 |
| collecting | 正在收集5帧整体中心稳定数据 |
| stable及CENTER坐标 | 三色圆台整体中心已稳定识别 |

更新时先停止MaixVision中正在运行的旧程序，重新打开并运行最新版vision.py。
需要开机生效时重新安装覆盖设备上的应用。若全流程已经到原料区、参考动作也完成，
画面仍只显示WAIT CAM，应继续检查相机/dev/ttyS2与STM32的UART4通信（115200）、
TX/RX连接及共地；不能把本地预览成功当作控制板通信已接通。

## 配置与部署

同时更新 `vision.py`、STM32、ESP32及App。完整机械臂流程必须开启视觉。
相机保持512×320、`/dev/ttyS2`、115200。视觉脚本内已合并原始
`识别/turntable_detector.py` 和 `识别/main.py` 的算法及LAB触屏标定，原文件不修改。

App“原料抓取”现在只显示一套“近车抓取位”，原中位置(R2)数值作为初值。
请重新实测伸缩、升降、夹爪开合、外部底座角度及车载存放位置；旧左/右参数不参与原料抓取。
车载槽1/2/3转盘角度仍独立按本批物料序号选取。调参时要确保张开的夹爪在等待姿态下
能够容纳转来的物块；相机需要看得到物块底座，避免夹爪遮挡识别区域。

## 截图抓放默认参数（2026-10-24）

暂按截图编号1/2/3对应画面左/中/右设置，位置选择仍由视觉/放置编号决定。
抓取与放下不同的伸长距离分别保留，不互相覆盖：

| 位置 | 抓取外部R/Z (mm) | 放下外部R/Z (mm) | 外部基座角度 |
|---|---|---|---|
| 左/1 | 154.0 / -128 | 152.0 / -128 | 209° |
| 中/2 | 119.0 / -126 | 120.0 / -126 | 170° |
| 右/3 | 185.0 / -120 | 185.0 / -120 | 134° |

车载存取点共用R=11.0mm、Z=-36mm、基座57°；合成速度300RPM，
抓取夹爪60°/秒、放下夹爪10°/秒，张开30°、闭合0°。
原料近车位采用抓取2，即119.0/-126、170°，送回车载点11.0/-36、57°。
这些值仅作为初始默认，仍需实车核对近车姿态。

用于R/G/P/T及堆叠K的默认参数统一保存在App的ScreenshotArmDefaults中。已有手动保存的
全流程参数和卡片库不被覆盖；全流程机械臂页提供“恢复截图抓放默认值”按钮，
套用R/G/P/T截图参数及用户指定的堆叠高度，不修改路线或已保存转盘角度。新安装的卡片库
提供截图六张抓放卡和两张可见转盘卡，不自动加入执行编排。

截图仅显示转盘0°和120°，第三角度没有显示。新安装暂用0/120/180°，
第三个180°沿用旧默认，尚待确认；已有转盘配置保留。用户补充堆叠高度比普通放下高10cm，因此K沿用相应放下参数，外部Z增加100mm：
左-28mm、中-26mm、右-20mm；其余伸长、基座角度、速度及夹爪参数与该位置放下一致。

## 一批原料的执行顺序

1. 按任务码确定本批三种颜色，TABLE联合筛选三色物块，通过椭圆几何检查后取三中心平均。
   整体中心最近5帧在中位中心1像素内，才输出坐标。底盘根据配置的目标X/Y校准，
   微调后重新收集图像；不按某个物块的颜色偏移底盘。
2. 校准成功时固定圆台几何：由三点均值和二阶矩估计椭圆轨迹。
   抓取点为椭圆画面最下方的点，即用户确认的近车位置，屏幕画黄色圆圈。
   原料区不再把当前三物块的左中右位置绑定为三套抓取姿态。
3. ESP32先选本次车载槽转盘角度，再发送RAW_READY。STM32执行正常抓取卡片的准备段：
   张开夹爪、旋转到外部角度、伸缩/升降到固定抓取点。两轴确认到位、开爪完成后暂停，
   返回ACTION/DONE。准备完成不会自动合爪，也不会提前累计一件搬运动作。
4. 此时开始新的NEAR请求，只等待任务码当前颜色；其他颜色先转来仍等待。
   目标中心必须在固定下方抓取点的小窗口内(椭圆短半轴12%，最小3、最大8像素)，
   且不得有其他已识别物块更靠下。连续5帧目标中心相对中位点偏移不超过2像素才确认。
   缺色、目标未到位、目标经过窗口时运动明显，均只返回NONE并继续等待。
5. ESP32只接受本次请求号、当前颜色及近车编号2；发RAW_TAKE后，STM32直接从合爪步骤
   继续，抬起并送到本次车载槽，不重复收回再伸出。完成后处理下一颜色。
6. 三件全部抓完、搬回车载槽后，才离开原料区。后两次等待保留圆台中心与抓取点，
   不要求三种颜色仍齐全；第二批到原料区时必须重新完成TABLE校准。

## 串口示例

```text
CAM,104,TABLE,156,256.0,160.0
VISION,104,TABLE,156,256.0,160.0
EXEC,105,RAW_READY,A,1100,-50,200,-40,20,60,0,60,0,248,140
ACTION,105,ACCEPTED,0
ACTION,105,DONE,0
CAM,106,NEAR,1
VISION,106,NONE
VISION,106,NEAR,1,2
EXEC,108,RAW_TAKE
ACTION,108,ACCEPTED,0
ACTION,108,DONE,0
```

NEAR响应中的2仅表示固定近车位，不再是三点中的颜色排序。原料区不使用PICK选左中右。
NEAR等待超过60秒会报RAW_TARGET_TIMEOUT，停止底盘与机械臂；停止、其他动作、故障会
使STM32保存的准备状态失效。没有成功准备时RAW_TAKE被拒绝。重复请求号不重复夹取。
RAW_READY和RAW_TAKE是全流程内部执行命令，App单独调试取放卡片保持原行为。

## LAB颜色标定

设备使用 `~/lab_thresholds.json`，与原识别程序共用。停止全流程后，相机显示
PREVIEW TABLE / WAIT CAM（空闲）时长按1.5秒进入标定：双击取样，调整L/A/B容差，NEXT保存，
无关颜色可SKIP。保存后重启继续使用；缺少标定时不使用默认阈值冒充识别成功。
无触屏设备先用原标定程序生成该JSON。活动任务中不进入标定。

颜色编号：1红、2黄、3蓝、4绿、5黑、6浅蓝；二维码决定当前批次的检测颜色和抓取顺序。

## 其他工位

加工区取回G和暂存堆叠K仍使用OCCUPIED：先识别三个物块，按画面X排序，以中间物块
底座圆心校准。完成一次校准后，逐件通过PICK确认目标颜色的固定左/中/右位置，
取走物块后保留位置参考，不把剩余物块重新编号。
空圆环放置P/T每组只对准RING中间位置一次，由任务码放置编号与processMap/storageMap
决定对应左/中/右固定参数。车载槽转盘角度与外部位置参数独立。

## 验证与边界

合成图像和Maix串口测试覆盖TABLE校准、近车方向、错误颜色、经过窗口时的移动、
5帧稳定、缺失后重新积累、下一颜色不得沿用历史、只剩一个物块时的近车识别。
控制测试覆盖准备后等待不合爪、直接合爪不重复伸出、错误/重复请求、取消后不可继续、
全25步路线与6次原料等待。App单元测试和两端固件构建也需通过。

这些检查不等于实机抓取成功。当前按观测到位触发合爪，不预测未来转台角度，
也没有物块夹紧/车载槽占用传感器反馈；需实测相机视角、光照、等待姿态及夹爪闭合时间。
