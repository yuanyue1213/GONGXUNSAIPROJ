# 回包检查与修复（2026-10-18）

本次检查确认以下代码问题并修复：

- ESP32手动命令入口不接受`QUERY,id`，命令被静默丢弃；全流程内部自己发送QUERY不受此问题影响。
- App的横移、原始脉冲转向使用旧MOVE指令，按旧协议没有应用回包；ESP32手动EXEC入口只接受陀螺仪命令，不能直接改为EXEC/MOVE。现在App与ESP32都支持EXEC/MOVE，复用STM32的ACTION状态。
- App仅在底盘“转向”标签显示moveStatus，“移动”页没有状态文本；外层moveRunning固定传false。现在各底盘标签均显示状态，根据本次手动动作序号处理运行/结束状态，等待3秒没有ACCEPTED时提示检查通信，禁止自动重发移动命令。
- App收到STATUS没有显示，且没有分段检测、原始RX/TX记录。现在连接页增加两项只读检测和最近24条可复制记录。
- 查询正在执行的同序号动作，现在返回ACTION/ACCEPTED；结束后仍通过8条结果缓存返回终态。使用新序号的QUERY查询全局STATUS。

这些问题不证明实车回线接通。之前App显示JY901S NOT_READY，只能证明当次IMU查询已通过STM32返回App，不能证明传感器收到有效数据或所有旧命令都提供回包。

## 无动作通信检测

在App“连接”页点击“检测双向通信（不驱动电机）”。协议：

```text
App -> ESP32: PING,123
ESP32 -> App: LINK,123,ESP_OK
ESP32 -> STM32: PING,123
STM32 -> ESP32 -> App: PONG,123,STM32
```

只有LINK意味着ESP32已处理请求，不代表STM32收到或执行动作。只有匹配本次序号的PONG才完成全链路检测，且也不代表电机动作完成。3秒未收到PONG时App区分“ESP32也未回应”和“ESP32已回应但STM32未回应”。旧序号不会误判本次检测成功；迟到的有效回应仍能更新结果。

“查询STM32状态”发送`QUERY,新序号`，显示空闲/忙碌、机械臂两轴原点是否有效及转盘命令目标角度。最后一项是舵机命令值，不是编码器实测角度。查询和PING在动作运行时也允许，不会驱动电机。查询已经缓存的EXEC序号可能返回ACTION终态，而不是STATUS。

## 接线与更新

|方向|接线|
|---|---|
|ESP32发命令|GPIO17 TX → STM32 PB11 RX|
|STM32返回|PB10 TX → ESP32 GPIO18 RX|
|共同参考|两板GND共地|
|串口|115200、8N1|

本次需同步更新App、ESP32和STM32。摄像头无需更新。若只有LINK没有PONG，检查上述回线以及实际烧录版本；若PONG正常，查看RX记录中是否有ACTION/ERROR或IMU/NOT_READY，按具体原因排查，不把ESP32应答当作STM32已执行。

旧手动机械臂/舵机/CMD/ALIGN/PLAN等接口仍按原协议工作，不会凭空新增执行完成回包；全流程使用的EXEC/ACTION接口保持原有完成/失败语义。TX记录仅表示App写入TCP成功，不能当作动作确认。停止按钮仍发送原来的停车请求，本次PING不替代停车确认。

软件验证：ESP查询及EXEC校验、STM32空闲/运动中PING与动作QUERY、App真实本地Socket上的拆分LINK/PONG/STATUS接收、序号隔离和检测超时、原有运动与任务回归测试。没有连接实车或执行烧录。
