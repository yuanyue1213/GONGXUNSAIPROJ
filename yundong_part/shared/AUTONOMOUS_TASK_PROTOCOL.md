## 摄像头请求与结果

另外提供已合并引导、分区和应用的 `hello_world/build_autonomous/robot_remote_full.bin`，该文件从0x0烧录；独立的 `robot_remote.bin` 仍从0x10000烧录。

ESP32 → STM32 → 摄像头：

```text
CAM,101,QR
CAM,102,MAT,5
CAM,102,MAT,5,256.0,160.0
CAM,103,RING,2
CAM,104,IDLE
```

QR读四组任务码。MAT的编号为颜色：1红、2黄、3蓝、4绿、5黑、6浅蓝。RING的1/2/3为画面左/中/右序号，ESP32按配置换算任务中的物理圆环编号。请求编号1—4294967295，重新定位后的请求必须使用新编号。

IDLE停止识别，只显示预览，不继续输出识别帧；用于关闭视觉的任务和任务结束/停止。

摄像头 → STM32 → ESP32：

```text
VISION,101,QR,156+123+516+231
VISION,102,MAT,5,113.2,160.7
VISION,103,RING,2,256.4,160.3
VISION,103,NONE
```

坐标为512×320全图坐标，保留一位小数；有效范围0≤X<512、0≤Y<320。结果连续三帧稳定后发送，坐标稳定阈值1.5px。请求模式持续生效并重复输出，相同编号的请求重传不清空稳定窗口。漏检或多同色候选不能唯一确定时输出NONE，不能使用旧中心代替新检测。ESP32仅消费当前请求、当前类型和当前目标的结果。

四组任务码必须满足：两组颜色各三种不同颜色且两批颜色集合一致，两组位置各为1/2/3的排列。第二批暂存位由第一批颜色—位置映射计算，例如 `156+123+516+231` 的第二批暂存位置是2、1、3。

物料识别允许剩余两件或单件，不再要求全部三件存在。圆环模式目前仍要求能可靠识别三组同心环；遮挡严重时会NONE和超时停止，不输出猜测位置。

```text
EXEC,206,ARM_POSE,0,0,0,20,3200

QUERY,207
```

MOVE、BASE、STATE/STATE_V2、ARM_POSE参数仍使用现有定义。PULSE为F/B/L/R方向、正整数脉冲数、5—300RPM，脉冲数1—1000000；用于浮点视觉误差到脉冲的最终取整，避免先把距离取整。STATE的T卡片按已知转盘起角到配置的槽位角度执行。

回包：

```text
ACTION,201,ACCEPTED,0
ACTION,201,DONE,0
ACTION,201,ERROR,FAULT
ACTION,201,BUSY,ACTIVE
ACTION,201,CANCELLED,STOP
STATUS,301,IDLE,1,0
```

STATUS字段是查询序号、IDLE/BUSY、机械臂零点是否就绪、最后成功发送的转盘角度。QUERY命中最近8个已结束自动动作时，重发该动作的终态；否则返回当前STATUS。活动指令重复则重发ACCEPTED，不执行第二遍；缓存中的同序号同指令重发终态，同序号改参数返回ERROR/REUSED。缓存之外不能保证任意历史指令去重，ESP32因此使用单调递增编号，不重发动作，丢失反馈只发QUERY。

MOVE/PULSE仅四轮均到位后DONE。STATE/STATE_V2仅完整卡片正常结束后DONE，故障取消不能当成功。舵机DONE表示软件轨迹已结束，不是编码器到位或物料抓取成功证明。动作总超时150s。自动动作持有执行权，手动动作被拒绝，停止命令仍有效。

旧App手动命令保持原格式和无应用层动作反馈行为。任务停止使用AUTO_STOP；兼容原CMD,S/Z/H/Q，ESP32在自动任务中收到任一种停止会停止整套任务。

## App → ESP32配置和一键启动

```text
AUTO_CFG,10,9889,9889,45,10,256.0,160.0,321,321,0,90,180
AUTO_OPTIONS,10,1,1,-
AUTO_DRIVE,10,3291,20
AUTO_ROUTE,10,0,2250,2200
AUTO_ROUTE,10,1,2200,2200
AUTO_ARM,10,R,1,STATE_V2,10,A,1100,-50,200,-40,20,60,0,60,0,248,140
AUTO_START,11,10
AUTO_STOP,12
```

AUTO_CFG字段：配置序号、前后每米脉冲、左右每米脉冲、路线RPM、细调RPM、目标图像X/Y、粗加工画面左中右编号、暂存画面左中右编号、车载槽1/2/3转盘角度。环编号映射必须是123的排列，三个槽角不同且0—270°。目标坐标为夹爪工作点对应的图像坐标，不能未标定就认为默认256/160准确。模板坐标相对于软件零点，不是世界地图坐标。

AUTO_OPTIONS字段：配置序号、视觉开关0/1、机械臂开关0/1、手动四组任务码或`-`。关闭视觉且开启机械臂时必须提供有效任务码，例如`AUTO_OPTIONS,10,0,1,156+123+516+231`。新App每次都发送OPTIONS，旧客户端未发OPTIONS时保持原来视觉与机械臂均开启的兼容行为。

AUTO_DRIVE字段：配置序号、原地转90°的每轮脉冲数（1—500000）、转向RPM（5—60）。每个CFG之后必须上传，缺少或无效则拒绝启动。App由`π×(前后轮距+左右轮距)/4×前进每米脉冲/1000×转向修正系数`计算，最后四舍五入；默认190mm、251.4mm、9889脉冲/m，按用户实测将系数设为0.96，得到3291脉冲（系数1时为3428）。180°使用两倍90°脉冲。实际转角需地面标定，参数独立保存于全流程页。旧版保存为1.0的全流程系数会一次性迁移至0.96，其他已保存标定值保留，之后修改也保留。该系数只校准旋转，不修正直行距离或横向偏移。CFG的旧左右每米脉冲字段保留解析兼容，新路线和视觉微调都使用前进标定。

AUTO_ROUTE字段：配置序号、节点索引0—19、世界X/Y坐标mm整数。新App上传全部20点，节点用途和顺序保持文末所列路线，坐标可调。坐标须满足灰色车道的车体中心约束，终点索引19必须是S2=(2250,150)。若修改后某段不能沿合法轴线到达，运行时停车报LANE_BOUNDARY，不跨越非车道区。

AUTO_ARM字段：配置序号、工位类型、车载槽编号、完整STATE_V2参数。它是全流程直接输入的机械臂参数，不引用卡片ID或卡片库。兼容旧AUTO_PROFILE帧。五类，每类三个槽，共15组参数：

|类型|App名称|模式|用途|
|---|---|---|---|
|R|原料抓取|A|从转盘抓取并存入车上|
|G|粗加工取回|A|从粗加工位抓取并存入车上|
|P|粗加工放置|P|从车上取出并放到粗加工位|
|T|第一批暂存|P|从车上取出并放到暂存位|
|K|第二批码垛|P|从车上取出并放到同色物料上|

全流程页的机械臂区按工位和槽位切换输入R/Z、合成速度、夹爪速度/角度、基座角度等参数，独立于调试卡片保存。三个槽位使用配置的转盘角度选择，参数中的r/z及基座角度需匹配实际工位和车载位置。A的r1/z1是外部取料点、r2/z2是车载存放点；P的r1/z1是车载取料点、r2/z2是外部放置点。码垛K须单独标定第二层高度。界面初值仅作为输入起点，不代表已实车标定。

配置按批次加载：每个有效AUTO_CFG清空本轮参数及路线、转向完成位。新App发送CFG、OPTIONS、DRIVE、20个ROUTE、按需15个ARM、START；开启机械臂共39帧，关闭机械臂共24帧。只有开启机械臂才要求15组参数齐全，关闭机械臂允许完全没有这些参数。任一配置帧无效会锁住本轮启动，须重新发送有效CFG开始一轮上传。配置在ESP32本轮RAM中，App独立持久保存输入并在每次启动前重新上传。重启后不得省略上传。

在App“全流程”页选择开关、填写路线/视觉/机械臂参数，车放在S1且车头朝下，点击“一键启动全流程”。开启机械臂时先在“机械臂”页初始化零点；关闭机械臂无需初始化，也不会自动收回机械臂，应在运行前手动置于合适姿态。启动检查STM32空闲，只有开启机械臂才检查零点和执行收回。任务结束或中断后，重新启动意味着重新从S1执行，不能在半路直接续跑。App后台/断开连接沿用原有停车逻辑；任务运行中保持屏幕常亮。

ESP32状态回App：

```text
AUTO,11,STARTING,0,0,0,0,S1_HEAD_DOWN
TASK,11,156+123+516+231
AUTO,11,WORK,4,0,1,1,CARD_DONE
AUTO,11,DONE,20,0,24,24,S2
AUTO,11,STOPPED,4,0,0,0,VISION_TIMEOUT
```

AUTO字段：运行序号、状态、路线节点索引、当前批次操作中的物料索引、已完成抓取动作数、已完成放置动作数、原因。抓放数是执行完成数量，不是视觉确认的正确抓放数量，不能直接当作规则要求的成功统计。物料颜色/位置正确性及真实抓取反馈需实车验证或进一步接入传感器。

## 已执行的路线和对准策略

```text
S1 → (2250,2200) → NE(2200,2200) → Q
→ NE → R(1200,2200)
→ C(1200,1200) → P(1200,300)
→ C → T(300,1200)
→ NW(300,2200) → R
→ C → P → C → T
→ C → Q → SE(2200,300) → (2250,300) → S2
```

完整模式下每个粗加工工位先全部三件放完，再全部三件取回。摄像头模式由当前步骤切换：取料/取回/码垛为对应颜色的MAT，空圆环放置为RING。每件先转基座和车载转盘，停稳后请求新视觉帧，再执行配置的取放参数。跨工位前执行ARM_POSE收回到软件r/z零位。关闭机械臂时跳过所有这些执行器动作；关闭视觉时跳过扫码和全部对准步骤；两项都关时只按20个路线节点行驶。

导航先选择合法的X/Y轴线，再原地转到该轴线的前进朝向；转向DONE后才前进，前进DONE后才更新位置。转向DONE后才更新估计朝向，失败或超时停车。使用MOVE,C/W,1000,RPM,目标脉冲编码精确旋转脉冲，位移使用MOVE,F，视觉微调使用PULSE,F。状态TURNING表示原地转向。

启用视觉或机械臂时，到工位后原地恢复初始车头朝下姿态，再识别或取放，沿用原相机映射和机械臂基座参数。视觉对准使用现有1.090819mm/px，浮点误差计算到最终脉冲取整。每次只修正一个世界坐标轴，单次最大25mm；按需转90°/180°，前进后转回朝下姿态，500ms停稳后以新请求重新识别，两个轴都在1px内才执行动作。单件最多20次修正，初始误差超过200mm停止；视觉等待60s超时。

直线段沿用示意图及300mm方形车体的车道检查；该检查不等于已验证整车原地旋转的扫掠空间。必须按实车外廓、机械臂收纳姿态与场边距离检查转弯净空。现有节点未改变，必要时在App调整途经点。

本版是固定节点路线，没有随机障碍感知/图搜索绕行、没有全局定位反馈，也不会自动搜索超出当前画面的随机二维码/转盘位置。里程以定距动作估算，工位依靠局部视觉修正；随机位置、轮胎滑移及障碍仍需后续感知接入。与运动规划中的动态路线方案相比，这是可联调的固定场地执行版，不能宣称已完成全部比赛环境适应能力。

### 2026-10-25 相机通信错误反馈

- STM32收到合法CAM请求后，尝试UART4发送，并向ESP32回传CAM_TX,id,OK或CAM_TX,id,ERROR。OK仅表示本地发送完成，不确认相机收到了；实际VISION,id,NONE或识别结果才证明相机返回数据。
- ESP32仅接受当前视觉等待编号的CAM_TX错误，停止并向App报告阶段:CAMERA_TX_FAILED。过期编号忽略。
- 每个新视觉请求重置camera_replied，重复发送同一请求不重置。60秒未收到合法且匹配的相机回包报告CAMERA_NO_RESPONSE；收到合法NONE但未完成稳定识别则沿用VISION_TIMEOUT/RAW_TARGET_TIMEOUT。单纯CAM_TX,id,OK不计相机已回应。
- App新增这三类通信状态的中文说明：发送失败、完全无相机回包、已收到相机回包等待稳定识别。
- MaixCAM脚本显式配置选定UART的pinmap；保留ttyS2默认值，现场A21/A22接线应明确设置为ttyS4。不会自动换端口。
