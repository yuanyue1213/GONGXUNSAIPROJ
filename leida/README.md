# N10 → ESP32-S3 → Wi-Fi → 电脑实时点云

`n10.py` 保留为原始串口/地图/A*参考，新程序不依赖它，也不需要 pyserial。
`hello_world` 已与运动工程共用同一份ESP32-S3合并桥源码：雷达UDP3334、App TCP3333、PC TCP3335。实车自动采样/规划用 `python n10_wifi.py --robot --zone 1`（1右下、2右上），操作和协议见 [PC导航说明](../yundong_partv2/docs/PC_NAVIGATION.md)。

不带 `--robot` 的下述操作仍是手动查看/虚拟预览，不会驱动车辆。

## 接线

| N10 | ESP32-S3 |
| --- | --- |
| TX（黄线） | GPIO16 / UART2 RX |
| RX（绿线） | GPIO15 / UART2 TX，可不接；当前不发送雷达控制指令 |
| GND | GND，必须共地 |
| VCC（红线） | 稳定 5V 电源，不能接 3.3V |

串口为 230400、8N1、3.3V TTL。确认开发板 GPIO15/16 已引出且无其他硬件占用。
UART0保留日志，UART1使用TX17/RX18与STM32通信。程序不会自动启动已被指令停转的雷达。

## 编译与烧录

在已激活的 ESP-IDF 6.x 终端运行（COMx 换成实际端口）：

```powershell
cd F:\GONGXUNSAIPROJ\leida\hello_world
idf.py build
idf.py -p COMx flash monitor
```

`sdkconfig.defaults` 默认目标 ESP32-S3；若目录已有其他芯片的 sdkconfig/build，先运行 `idf.py set-target esp32s3`。
烧录后 ESP 创建热点 **RobotCar-ESP32S3**，密码 **robotcar123**，地址 `192.168.4.1`。

## 电脑显示

电脑连接上述热点，保持连接，即使 Windows 提示“无 Internet”。然后运行：

```powershell
cd F:\GONGXUNSAIPROJ\leida
python -m pip install -r requirements.txt
python n10_wifi.py
```

若防火墙询问，允许 Python 的本地网络访问。电脑无需串口连接雷达。
默认使用 UDP 3334；可用 `--esp 192.168.4.1 --port 3334` 指定地址。

- 默认 5×5 场地图；`M` 可切换到 360° 雷达视图：车与雷达在中心，0°朝车头（画面上），+90°朝车身左侧，与原N10场地坐标变换保持一致；`+/-` 调整雷达视图量程。
- `M` 切换雷达/场地图；`1/2` 选择右下/右上起始区；`Q` 或 Esc 退出。
- 场地图使用已确认的非等宽5×5格：从左到右列宽400/450/400/450/550，从上到下行高470/450/400/450/400 mm。格区2250×2170 mm，距场地左侧150、顶部80、底部150 mm。车与雷达共用一个位姿，默认雷达安装在车中心、零度朝车头。按1为右下格中心 `(2125,350)`、车头向上；按2为右上格中心 `(2125,2085)`、车头向下。键盘1/2沿用右下/右上的选择顺序，不等同于赛道图的启停区编号。
- 点云为滚动更新，默认点有效期 0.35 秒（`--max-age` 可调）。断流后旧点自动清除并显示 `WAITING / NO DATA`，界面不会阻塞等待网络。
- `lost` 为订阅期间 UDP 序号缺口，`bad` 为收到的无效包；乱序/重复包丢弃，断流两秒后允许 ESP 重启序号。丢包不重传。

无硬件预览（合成数据，有 DEMO 标记）：

```powershell
python n10_wifi.py --demo --range-mm 3000
python n10_wifi.py --view map --zone 1
```

## 两次点击保存与格子通断

在点云显示窗口内单击鼠标左键两次（不必双击，也不是用鼠标指定障碍格）：每次保存点击时屏幕显示的点云状态。点击前先用键盘1/2或底部起点按钮选择车与雷达实际所在的右下/右上格中心；两次可以分别使用不同位置，但必须与实际摆放及朝向一致。旧版固定在(2250,150)/(2250,2250)换算的快照不再对应新的中心位姿，应重新采样。

- 四个450×450加工格，即(行2,列2)、(行2,列4)、(行4,列2)、(行4,列4)，永久不通，显示灰色BLOCK。
- 任意一次快照有至少一个有效测距点落入某格，该格就不通，显示红色BLOCK；两次命中格取并集。采样使用过的起点格除外：位置1对应(行5,列5)，位置2对应(行1,列5)。起点格的点云照常显示和保存，但不作为障碍；第二次选择新的起点时，也会清除该起点格在第一次采样中的障碍标记。JSON的ignored_start_cells记录本组豁免的起点格。绿色OPEN代表未被本规则封锁，不保证实车通过所需的宽度或整格都已被雷达观测。
- 使用全部360°有效点作坐标换算，格区外的点不参与判定。点在内部格线时归右边/下边的格，外侧最大边界不计入格区。
- 采样后屏幕保留空心采样点；实时点云继续刷新，已采样格子的通断不会随实时点消失而改变。
- 窗口底部显示Saved 0/2、1/2、2/2；两次完成后忽略后续采样并提示按R重开。无新鲜点云时拒绝采样；文件写入失败不消耗次数。
- 默认保存到`leida/captures/日期时间-随机编号.json`；第一次点击立即写入，第二次原子更新同一文件并标记complete=true。文件保存每次的点击时间、位置/朝向约定、点云极坐标与场地毫米坐标、命中格，以及最终blocked和5×5 passable布尔矩阵（true=通，false=不通）。行从上往下、列从左往右。
- 按R开始新的一对采样，旧JSON保留；重新启动程序不自动加载旧结果。`--save-dir 路径`可指定保存目录。DEMO模式保存的文件带demo=true，属于合成数据。

## 路径规划与虚拟小车

完成两次采样后，在底部点击“起点：右上↓”或“起点：右下↑”，再点“路径规划 / PLAN”，虚拟小车立即沿路线播放。也可按P规划、空格暂停/继续；按钮支持暂停/继续、重新播放。按钮不会消耗点云采样次数。

- 右上起点是(1,5)，车头初始向下；右下起点是(5,5)，车头初始向上。**底部起点按钮与键盘1/2现在统一选择车和雷达的位置、朝向及规划起点**，切换时清除旧动画，保留已保存的场地点云快照。选错实际位置会导致错误的障碍地图。
- 按“格子通就能走”处理，不检查车身尺寸。小车从所选起点格中心出发、回到同一格中心；路径全部沿相邻格中心连线，转向在格中心进行。雷达中心环与车中心重合，实时点云按同一车身位姿投影，随车平移和转向；已保存快照的场地坐标保持不变。旧的独立固定雷达圆点已移除，红箭头标车头，青色线标车身右侧。
- 仅前进F、后退B、左转90°L、右转90°R；箭头表示车头，即使后退也不反转车头。连续同类型直行合并成一段，经过中间格不停车，距离按非等宽格子的中心坐标计算。
- 全任务顺序：起点→二维码(3,5)→原料1(1,3)→粗加工1(5,3)→暂存1(3,1)→原料2→粗加工2→暂存2→原起点。粗加工代表三件放置、再取回，暂存第二批代表同色码垛；这里只以停顿及状态标签演示工位任务，不模拟机械臂。
- 每个任务工位在到达正确格子并满足朝向后，才进入任务停顿：二维码(3,5)车头向上，车右侧朝右边界；原料(1,3)车头向左，车右侧朝上边界；粗加工(5,3)车头向右，车右侧朝下边界；暂存(3,1)车头向下，车右侧朝左边界。两批取放均执行相同的工位朝向约束，返回起点暂不额外限制终态朝向。
- A*搜索状态包含任务阶段、行、列、朝向，联合优化全程到达朝向。预览默认前进/后退400mm/s、每次90°转向0.8秒；工位停顿演示1秒，播放默认2倍速。这些是动画参数，非实车标定或比赛用时预测。
- 全路线显示为蓝色，当前直行段显示为黄色，小车为绿色、红箭头为车头。底部显示前进/后退/转向/当前工位及动作进度；最后显示DONE。
- 工位被封锁或不可达时显示具体错误，不播放部分路线，不擅自放宽障碍。不足两次采样时拒绝规划。更换规划起点、成功新增采样或按R重置后，旧规划会清除。
- 这次功能仅在电脑播放虚拟小车，不会向ESP/STM32发送行驶命令；无需重烧ESP。运行前更新依赖：`python -m pip install -r requirements.txt`。
- 绑定的是虚拟车位姿，不是实车定位反馈，不含SLAM；实物雷达不随虚拟车实际运动时，播放过程中的实时点云投影仅用于演示。两次采样应在实际位姿与所选起点一致时完成，JSON的car_radar_pose_mm_deg记录当时共用的X/Y/车头角度（从地图上方顺时针计）。

## 协议与排障

电脑每秒向 ESP UDP 3334 发送 ASCII `N10_SUB`（7字节）。ESP 将数据发送到订阅包的源 IP/端口，五秒不续订则停止发送；只支持一个活动查看器，后来的订阅者会替换前者。
每个UDP包固定66字节：`N10U`（4字节）+ uint32大端序号（4字节）+ N10原始帧（58字节）。序号对每个校验通过的原始帧递增，uint32回绕。

N10原始帧：`A5 5A 3A` + 两字节扇区周期(us) + 两字节起始角度(0.01°) + 16组[两字节距离(mm)、一字节强度] + 两字节结束角度 + 一字节校验。多字节量均为大端；校验为前57字节之和取低8位。跨0°插值，16点间隔为角跨度/15，零距离忽略。

ESP 每五秒输出累计 `valid / invalid / uart_errors / send_errors / viewer`：

- `valid=0`：检查黄线是否接 GPIO16、共地、5V供电和雷达是否旋转。
- `invalid` 或 `uart_errors` 持续增多：检查接线、电平、干扰及供电。
- `viewer=offline`：检查电脑热点连接、Python运行状态和防火墙。
- 有有效帧但无图：检查电脑 `bad/lost`、量程、所选视图及位置；场地图只显示场内的点。

软件验证（在项目根目录）：`python -m unittest discover -s leida -p "test_n10_*.py" -v`。
UART解析器另有 `test_n10_protocol.c`，可用主机GCC编译运行。软件测试不能替代实物接线、无线和雷达数据验证。
