# ILI9341任务码屏

屏幕为DevEBox SPI_TFT280，320×240。厂商资料：https://www.xinlucity.com/?s=resourcedetail/index/id/150.html 。初始化参考该页的“2.4&2.8寸通用例程（带字库）”，使用ILI9341软件复位0x01，不操作外部RST，不依赖板载字库。

## 接线

| 屏幕脚位 | STM32 |
|---|---|
| 1 VCC | 3.3V |
| 2 GND | GND |
| 3 SDI | PB2 |
| 4 SCL | PC10 |
| 5 CS | PE2 |
| 6 SDO | 不接；不读字库 |
| 7 D/C | PD11 |
| 8 BLK | PE1，高电平点亮 |

主板PE1虽然标LCD_RST，按实物必须用作背光。上下排针方向不同，应按信号名接线。

使用GPIO软件SPI，不占用新的定时器、DMA或串口。引脚、SPI延时和横屏方向在`robot_config.h`的`LCD_*`配置。默认`LCD_MADCTL=0x28`，反向横屏改0xE8。任务码和进度改变时局部刷新，不持续刷屏，不关中断。

## 独立测试

在STM32工程目录执行`cmake --preset ScreenTest`、`cmake --build --preset ScreenTest`，烧录`build/ScreenTest/yundongv2.hex`。VS Code运行和调试也可选择“STM32 · 固定任务码屏幕测试（上电显示，无电机）”。若停在main，继续运行。

本固件只初始化系统、GPIO和屏幕，不初始化电机、舵机PWM或串口任务，不需要App。上电固定显示`MISSION_FIXED_QR_TEXT`（123+321+132+312），进度均未完成，不自动演示虚假完成状态。

## 显示和完成标记

横屏2×2：上排第一批，下排第二批；每排左边三位颜色、右边三位工位。按左上、右上、左下、右下读取即二维码的四组数据。12位数字同时可见，笔画高度均为80像素，无滚动、无翻页。

每位数字下方四格依次表示原料抓取、加工放置、加工取回、最终暂存/堆叠。对应取放动作成功后格子变绿；该件四步全部完成后，颜色和对应工位数字一起变绿。底部24格显示24次物料转移进度。

边框：蓝色等待、橙色执行、绿色全流程完成、红色失败。重新开始清除上一轮任务码和进度。完整流程扫码成功后显示真实任务码；FixedQr/StackTest加载配置任务码。StackTest只更新第二批最终堆叠进度，不补造其他阶段记录。

按2.8寸4:3有效显示比例估算，80像素约14.2mm；2.4寸约12.2mm。最终需在实物上测量数字笔画高度≥12mm，并安装在机器人上部醒目且无遮挡的位置。模拟和编译通过不代表硬件已点亮。

## 文件

`lcd_bus.c`负责GPIO SPI和背光；`task_display.c`负责ILI9341、大数字及进度；`mission_runner.c`在收到任务码和成功取放后更新。不改变动作顺序、速度、校准或App协议。
